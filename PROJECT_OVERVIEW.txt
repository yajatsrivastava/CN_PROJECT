1. EXECUTIVE SUMMARY & PURPOSE
------------------------------
This project is an end-to-end reliable, message-oriented transport layer protocol
called KTP (KGP Transport Protocol) implemented on top of unreliable UDP sockets
using C on Linux. It was developed for the Computer Networks Laboratory coursework
(IIT Kharagpur CS39006 assignment specification).

Key Architectural Constraints:
- Transport: Built entirely on top of POSIX UDP datagram sockets (SOCK_DGRAM).
- Orientation: Message-oriented (atomic 512-byte payload chunks), NOT byte-stream.
- Socket Abstraction: Custom socket type SOCK_KTP mimicking standard BSD socket
  calls (k_socket, k_bind, k_sendto, k_recvfrom, k_close).
- Delivery Guarantees: Reliable, strictly in-order, duplicate-free delivery with
  sliding-window flow control (swnd and rwnd).
- Channel Simulation: Packet drop emulation using dropMessage(float p).
- Deliverable Format: A static library libksocket.a built with 'ar rcs', companion
  header ksocket.h, daemon initksocket.c, test clients user1.c and user2.c,
  Makefiles, and documentation.txt.


2. SYSTEM ARCHITECTURE & COMPONENTS
-----------------------------------
Shared Memory Segment (SM):
- Segment key: ftok("ksocket.h", 'K') with fallback 0x4B545031 ("KTP1").
- Size: ~1.1 MB.
- Synchronization: Protected by a process-shared robust POSIX mutex
  (pthread_mutex_t initialized with PTHREAD_PROCESS_SHARED and PTHREAD_MUTEX_ROBUST).
  If any client crashes while holding the lock, the kernel flags EOWNERDEAD,
  allowing pthread_mutex_consistent() recovery without permanent deadlock.

Table Structure: SM[0 .. MAX_SOCKETS - 1] (MAX_SOCKETS = 20):
Each socket entry contains:
- is_allocated, pid, udp_sock, is_bound.
- src_addr (local IP/port), dest_addr (remote IP/port).
- send_buf[20]: Fixed-size array of 512-byte messages + status flags.
- recv_buf[10]: Fixed-size array of 10 message slots (as specified).
- swnd: Sender Window (start_seq, next_seq, window_size, in-flight unACKed).
- rwnd: Receiver Window (expected_seq, last_in_order_seq, window_size, out-of-order buffer).
- nospace, nospace_update_pending, last_ack_sent_time, last_probe_time.
- Statistics counters: total_transmissions, total_data_msgs.

Processes and Threads:
1. User Applications (user1.c / user2.c / grading tests):
   Link with libksocket.a and invoke k_socket, k_bind, k_sendto, k_recvfrom, k_close.
2. initksocket Daemon:
   - Thread R (Receiver): Listens with select() on active UDP sockets, processes
     data and ACKs, buffers out-of-order data, delivers in-order cascading packets,
     and periodically re-advertises window updates.
   - Thread S (Sender / Timer): Wakes up periodically (T/2 = 2.5s), checks timeout T = 5s,
     retransmits unACKed messages, transmits new pending messages from send_buf within
     swnd, and sends zero-window probes.
   - Garbage Collector: Child process created via fork(). Checks kill(owner_pid, 0)
     every 2 seconds. Automatically reclaims sockets if client processes crash.


3. PROTOCOL OPERATION & STATE MACHINE
-------------------------------------
A. Sequence Numbers:
- 8-bit unsigned integers starting at 1 and wrapping from 255 back to 1.
- Progresses via ktp_next_seq(seq): (seq == 255) ? 1 : seq + 1.
- Distance via ktp_seq_diff(a, b): forward distance modulo 255.

B. Sender Flow Control (swnd):
- Initial window size: 10 messages.
- Upper-bounded by minimum of SWND_MAX_SIZE (10) and receiver's advertised rwnd.
- Application writes 512B chunks into send_buf.
- Thread S transmits up to swnd.window_size packets in-flight.
- When an ACK arrives, window slides forward, freeing buffer slots.

C. Receiver Flow Control (rwnd) & Buffering:
- Buffer size: 10 messages.
- Advertised rwnd is always the number of free slots in recv_buf.
- In-Order Arrival (seq == expected_seq):
  1. Stored in recv_buf with is_in_order = 1.
  2. expected_seq advances.
  3. Cascading delivery: Any previously buffered out-of-order packets that are
     now consecutive are marked is_in_order = 1, advancing expected_seq.
  4. Sends cumulative ACK with ack_num = last_in_order_seq and updated rwnd.
- Out-of-Order Arrival (seq > expected_seq within rwnd):
  1. Stored in recv_buf with is_in_order = 0.
  2. NO ACK sent (as explicitly mandated by assignment).
- Duplicate Arrival (seq < expected_seq):
  1. Payload discarded.
  2. Cumulative ACK re-transmitted to prevent sender stalling.


4. KEY PROBLEMS SOLVED
----------------------
A. The Zero-Window Deadlock ("Problem Here" in assignment):
- Issue: If recv_buf fills up, rwnd = 0 is advertised and nospace = 1 is set.
  When the application reads data and frees space, Thread R sends a duplicate ACK
  with updated rwnd. If that single ACK is dropped by dropMessage(p), and Thread R
  had reset nospace = 0, the sender stays stuck at swnd = 0 forever.
- Solution Implemented:
  1. Persistent Re-announcement: Thread R sets nospace_update_pending and keeps
     re-transmitting the window update on select() timeouts until the sender resumes
     sending data.
  2. Persist Timer (Thread S): If swnd == 0 and messages are pending, Thread S sends
     a Zero-Window Probe every T seconds to query the receiver.

B. Crash Resilience:
- Robust POSIX Mutex: Recovers from killed processes via PTHREAD_MUTEX_ROBUST.
- Garbage Collector: Automatically detects dead process PIDs and cleans up sockets.

6. BUILD AND EXECUTION GUIDE (LINUX)
------------------------------------
Prerequisites:
  sudo apt install -y build-essential make binutils tar diffutils

Build Commands:
  make all          # Compiles libksocket.a, initksocket, user1, and user2
  make libksocket.a # Compiles only the static library
  make initksocket  # Compiles daemon executable
  make user1        # Compiles sender executable
  make user2        # Compiles receiver executable
  make tar          # Packages ktp_submission.tar.gz for submission
  make clean        # Cleans object files, libraries, executables, and test logs

Manual Execution Steps:
1. In Terminal 1 (Start Daemon with drop probability p):
   ./initksocket 0.05

2. In Terminal 2 (Start Receiver):
   ./user2 test_output.txt 8082 8081

3. In Terminal 3 (Start Sender):
   ./user1 test_input.txt 8081 8082

Automated Experiments:
  chmod +x run_experiments.sh
  ./run_experiments.sh
